# He Design 交互规则

## 1. 交互不是额外层，而是结构延伸

页面交互必须服务于信息结构。好的交互会强化用户该看什么、该点什么、该如何理解页面；差的交互会制造噪声，让次级信息比主信息更显眼。

## 2. 交互强弱分层

### 一级交互

适用：

- 主 CTA
- 关键切换
- 页面核心输入

要求：

- 明确可见
- 状态差异清楚
- 激活反馈直接
- 数量受控

### 二级交互

适用：

- 次级按钮
- 标签筛选
- 折叠展开
- 局部跳转

要求：

- 不能抢主 CTA 的视觉中心
- 应保持统一反馈方式

### 三级交互

适用：

- 辅助提示
- 悬浮说明
- 轻微显隐

要求：

- 弱存在感
- 不打断阅读主路径

## 3. 状态设计规范

每个可交互元素至少考虑以下状态：

- `default`
- `hover`
- `active`
- `focus`
- `disabled`

执行原则：

- `hover` 用于表达“可点击”，不是重新设计一个新按钮
- `active` 应更靠近“确认执行”，而不是夸张动画
- `focus` 必须清晰，不能只靠颜色细微变化
- `disabled` 仍要保持可识别，但不能像正常态一样诱导点击

## 4. 动效原则

### 能用静态解决，就不要强行动

如果层级、颜色、留白已经足够表达关系，不要再加无意义动效。

### 动效只解决三类问题

1. 指出状态变化
2. 帮助空间连续性理解
3. 强化关键反馈

### 常见建议

- hover 轻微位移或阴影增强即可
- 面板展开优先用高度和透明度过渡
- 页面首屏不要堆多组同时运动
- 自动轮播、自动闪烁、持续脉冲要极度克制

## 5. 常见组件的交互约束

### 按钮

- 主按钮只能有一个最强视觉等级
- 次按钮通过描边、低对比底色或文字按钮体现
- 危险操作不要与主按钮同色同级

### 卡片

- 可点击卡片要整体可点击，不要只让小区域可点
- hover 可以强化边框、阴影或上浮，但不要变成另一种卡片
- 卡片里的二级按钮不能比卡片标题更跳

### 标签与筛选

- 选中态应显著，但不应像主 CTA
- 多选和单选要在视觉上清楚区分
- 标签过多时优先分组或折叠

### 表单

- 主输入路径要顺滑，避免同时出现大量同级强调
- 错误态优先清楚解释，不要只给红色
- 占位文字不能替代标签语义

### 列表与表格

- 行 hover 只做轻反馈
- 选中态要稳定，不因 hover 丢失
- 操作列不要成为页面最抢眼区域

## 6. 页面级交互骨架

### 发布型页面

- 交互以主按钮和锚点跳转为主
- 动效用于增强质感，不用于制造噱头
- 允许少量滚动入场，但不应破坏稳重气质

### 说明型页面

- 交互以展开、定位、步骤切换、目录导航为主
- 首先保证阅读效率
- 所有反馈都应帮助理解结构

### 传播型页面

- 可以允许更强的转场和情绪动效
- 仍应保留明确主操作和内容落点
- 不要因为氛围而牺牲可读性

## 7. 开发落地建议

当把交互规则翻译成代码时：

- 优先抽象状态类名或状态 token
- 使用统一过渡时长和缓动
- 对 hover 和 focus 分别设计，不能互相代替
- 键盘可达性和焦点可见性不能省略
- 加动效前先确认是否会打断信息主次

## 8. 风险信号

以下现象通常说明交互已经破坏结构：

- 页面上多个按钮都像主按钮
- hover 后次级元素比标题更醒目
- 面板、弹层、提示同时出现多个动画中心
- disabled 态仍像可点击状态
- 轻提示组件承担了主要表达任务
